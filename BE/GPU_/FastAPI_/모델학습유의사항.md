# FastAPI 모델 학습 연동 유의사항

## 1. 문서 목적

이 문서는 AI 담당자가 `BE/GPU_/FastAPI_`에 실제 UMI 모델 학습 코드를 연결할 때 지켜야 할 API 계약, 파일 계약, 상태 전이 및 구현 경계를 정리한다.

기준 문서는 다음과 같다.

- `BE/docs/API명세서v1.7.0.md`의 22절과 24절
- `BE/docs/인터페이스계약v1.5.0.md`의 7절
- 현재 `BE/GPU_/FastAPI_` 구현

계약 문서와 코드가 다르면 임의로 필드를 변경하지 말고 백엔드 담당자와 먼저 합의한다. 특히 요청·응답 필드명, 상태값, CKPT 메타데이터는 GPU Spring Boot와 직접 연결되므로 일방적으로 변경하면 안 된다.

## 2. 전체 책임 경계

| 구성 요소 | 책임 |
|---|---|
| EC2 Spring Boot | 학습 큐, TrainingJob, 입력 snapshot, attempt·lease, 최종 상태, SkillVersion 및 배포 게이트 |
| GPU Spring Boot | EC2 claim·heartbeat, Episode·기준 CKPT 다운로드 및 1차 검증, FastAPI 호출, EC2 진행 보고, CKPT Presigned PUT 업로드 |
| FastAPI | 로컬 학습 실행 접수·조회·취소·lease 관리, 실행 프로세스 감독, 진행 상태 및 CKPT 결과 생성 |
| AI 학습 코드 | Episode 전처리, 모델 학습 또는 추가 학습, 진행률 보고, 최종 CKPT 파일 생성 |

AI 학습 코드는 다음 작업을 직접 수행하지 않는다.

- EC2 PostgreSQL 또는 Redis 접근
- EC2 학습 작업 claim
- S3 Episode 다운로드
- S3 CKPT 업로드
- SkillVersion 또는 TrainingJob 상태 변경
- EC2 leaseToken 관리
- EC2용 진행 이벤트 ID·sequence 생성

## 3. 현재 코드에서 교체할 위치

실제 학습 코드를 연결할 기본 경계는 다음 파일이다.

```text
app/trainer/training_adapter.py
└── TrainingAdapter.train(request, output, reporter, duration_seconds)
```

현재 `TrainingAdapter`는 진행 상황을 모사하고 작은 JSON 파일을 CKPT 대신 생성하는 임시 구현이다. 실제 연동 시 이 메서드 내부를 AI 학습 진입점 호출로 교체한다.

가능하면 다음 파일의 역할은 유지한다.

| 파일 | 유지할 역할 |
|---|---|
| `app/trainer/entrypoint.py` | 별도 프로세스 진입, 요청 로드, 결과 경로 결정, 최종 상태 기록 |
| `app/trainer/progress_reporter.py` | atomic progress 파일 기록과 sequence 증가 |
| `app/trainer/checkpoint_manifest.py` | GPU Spring Boot에 전달할 CKPT 메타데이터 생성 |
| `app/infrastructure/process/*` | 학습 프로세스 생성·종료·상태 확인 |
| `app/supervisor/*` | 프로세스 감시, lease 만료, 완료 콜백 재시도 |
| `app/infrastructure/persistence/file_run_repository.py` | 재시작 복구용 로컬 실행 journal |

대규모 AI 저장소를 직접 섞어야 한다면 `TrainingAdapter`가 AI 코드의 진입 함수를 호출하도록 하고, FastAPI의 API·supervisor·journal 계층은 AI 라이브러리에 의존하지 않게 유지하는 것을 권장한다.

## 4. FastAPI 내부 API 계약

### 4.1 학습 실행 생성

```http
POST /internal/training-runs
Authorization: Bearer <FASTAPI_SERVICE_TOKEN>
```

주요 입력은 다음과 같다.

| 필드 | 의미 | AI 코드 처리 |
|---|---|---|
| `trainingJobId` | EC2 학습 작업 ID | 실행 디렉터리·로그 상관관계 식별에 사용 |
| `attempt` | 현재 실행 시도 번호 | 재할당된 이전 attempt 결과와 섞지 않음 |
| `gpuIndex` | 할당된 논리 GPU 번호 | 학습 프로세스가 지정 GPU만 사용하도록 적용 |
| `trainingMode` | `FROM_SCRATCH` 또는 `FINE_TUNE` | 학습 초기화 방식을 결정 |
| `baseModel` | 추가 학습용 기준 CKPT | `FINE_TUNE`에서만 사용 |
| `trainingProfile` | 고정 학습 프로필 | 하이퍼파라미터를 임의 변경하지 않음 |
| `inputSnapshotSha256` | 고정 Episode 입력 목록 hash | 실행 동일성 검증에 사용 |
| `episodes` | 순서가 고정된 Episode 목록 | `inputOrder` 순서로 처리 |
| `executionLeaseExpiresAt` | 로컬 실행 허용 기한 | 만료 후 계속 학습하지 않음 |

`runId`는 `{trainingJobId}:{attempt}`다. 같은 runId와 동일 입력의 재요청은 새 학습을 시작하지 않고 기존 실행을 반환해야 한다. 입력이 다르면 `409 RUN_REQUEST_CONFLICT`다.

### 4.2 상태 조회

```http
GET /internal/training-runs/{url-encoded runId}
```

상태는 다음 값만 사용한다.

```text
STARTING
RUNNING
CANCEL_REQUESTED
CANCELED
COMPLETED
FAILED
LOST
```

단계는 다음 값을 기본으로 사용한다.

```text
STARTING
PREPROCESSING
TRAINING
CHECKPOINT_CREATING
CHECKPOINT_READY
CANCELED
FAILED
```

새로운 세부 단계가 필요하면 기존 상태를 바꾸지 말고 먼저 GPU Spring Boot DTO 및 API 계약과 함께 확장한다.

### 4.3 취소

```http
POST /internal/training-runs/{runId}/cancel
```

- 취소 접수 시 즉시 성공 완료로 처리하지 않는다.
- `CANCEL_REQUESTED`를 기록한 뒤 학습 프로세스와 자식 프로세스가 실제 종료된 것을 확인하고 `CANCELED`로 변경한다.
- 학습 루프는 epoch·step 사이에서 취소 신호를 확인할 수 있어야 한다.
- 정상 종료 유예 시간을 넘으면 supervisor가 프로세스 그룹을 강제 종료할 수 있다.
- 이미 취소가 확정된 실행이 뒤늦게 CKPT를 생성해도 `COMPLETED`로 바꾸지 않는다.

### 4.4 실행 lease 갱신

```http
PATCH /internal/training-runs/{runId}/lease
```

- FastAPI lease는 EC2 lease보다 길어지면 안 된다.
- lease 만료 시 학습 프로세스를 중단해야 한다.
- AI 학습 코드가 긴 native 연산으로 Python 제어권을 오래 반환하지 않는다면 별도 watchdog이 프로세스를 종료할 수 있어야 한다.
- 시스템 시각은 UTC/NTP 동기화를 전제로 한다.

### 4.5 완료 콜백

FastAPI는 CKPT 생성과 검증이 끝난 뒤 GPU Spring Boot로 다음 요청을 보낸다.

```http
POST {GPU_SPRING_BASE_URL}/internal/training-runs/{runId}/completion
Authorization: Bearer <GPU_SPRING_CALLBACK_TOKEN>
```

완료 콜백은 재시도될 수 있으므로 다음 값은 최초 생성 후 바꾸지 않는다.

- `eventId`
- `modelCompletedAt`
- `checkpointStorageKey`
- `sizeBytes`
- `sha256`
- 전체 `metadata`

HTTP `202`는 GPU Spring Boot가 콜백을 접수했다는 의미일 뿐, S3 업로드와 EC2 최종 성공까지 완료됐다는 의미가 아니다.

## 5. 입력 파일 처리

### 5.1 Episode 위치

GPU Spring Boot가 S3에서 다운로드하고 크기·SHA-256을 검증한 ZIP을 공유 볼륨에 저장한 뒤 FastAPI에 상대 `storageKey`로 전달한다.

```text
{GPU_STORAGE_ROOT}/training-inputs/{trainingJobId}/{attempt}/{episodeId}.zip
```

FastAPI와 AI 코드는 다음 규칙을 지킨다.

- `SHARED_STORAGE_ROOT` 아래 경로만 허용한다.
- `..`, 절대 경로, symlink를 이용한 root 이탈을 허용하지 않는다.
- 전달받은 SHA-256을 학습 시작 전에 다시 검증한다.
- Episode 원본 ZIP을 수정하거나 덮어쓰지 않는다.
- 입력은 `inputOrder` 오름차순으로 사용한다.
- 같은 runId 재개 시 다른 Episode로 교체하지 않는다.
- Presigned URL이나 S3 자격 증명은 FastAPI에 전달되지 않는다.

Episode ZIP 기본 구조는 다음과 같다.

```text
<session_id>.zip
├── meta.json
├── summary.json
├── frames.csv
├── pose.csv
├── imu.csv
├── gripper.csv
└── frames/
    ├── 000000.jpg
    └── ...
```

현재 계약에서는 `gripper.csv`가 헤더만 있고 샘플이 0건이어도 입력 자체를 거부하지 않는다. 모델이 gripper 값이 반드시 필요하다면 AI 전처리에서 대체·후처리 정책을 명시하고 백엔드 계약과 별도로 합의한다.

### 5.2 추가 학습 기준 CKPT

`trainingMode=FINE_TUNE`이면 `baseModel`이 필수다.

```text
{GPU_STORAGE_ROOT}/training-inputs/{trainingJobId}/{attempt}/base-model/model.tgz
```

- `FROM_SCRATCH`에서는 `baseModel`을 사용하지 않는다.
- `FINE_TUNE`에서는 파일 존재와 SHA-256을 다시 확인한 뒤 로드한다.
- 기준 CKPT의 architecture, framework, contractVersion이 현재 학습 코드와 호환되는지 검사한다.
- optimizer state 포함 여부처럼 추가 학습에 필요한 CKPT 내부 구조는 AI 팀이 버전 계약으로 확정해야 한다.
- PyTorch 전체 객체 pickle보다는 `state_dict`와 명시적 manifest 조합을 권장한다.
- 신뢰할 수 없는 CKPT를 `torch.load`로 로드하면 코드 실행 위험이 있으므로 S3 및 EC2 검증을 통과한 파일만 로드한다.

## 6. 고정 학습 프로필

현재 지원 알고리즘은 `ACT`이며 학습 하이퍼파라미터는 웹 요청에서 임의로 전달하지 않는다.

```json
{
  "profileKey": "umi-act-default",
  "profileVersion": 1,
  "algorithm": "ACT",
  "hyperparameters": {
    "epochs": 100,
    "batchSize": 8,
    "seed": 42,
    "learningRate": 0.0001,
    "optimizer": "AdamW"
  },
  "configSha256": "64자리 소문자 SHA-256"
}
```

- 요청의 하이퍼파라미터를 코드 기본값으로 덮어쓰지 않는다.
- 지원하지 않는 profile·algorithm이면 학습을 시작하지 않고 `422 UNSUPPORTED_TRAINING_PROFILE`로 거부한다.
- canonical JSON으로 계산한 설정 hash가 `configSha256`과 맞아야 한다.
- seed를 Python, NumPy, PyTorch 및 DataLoader worker에 일관되게 적용한다.
- 재현성 옵션과 성능 옵션의 차이가 있다면 실행 로그 또는 모델 manifest에 기록한다.

## 7. GPU 자원 사용

- 요청의 `gpuIndex`를 실제 학습 프로세스에 적용한다.
- Compose에서 물리 GPU 2만 노출하는 환경에서는 컨테이너 내부 GPU 번호가 `0`으로 보일 수 있다. 호스트 번호를 코드에 하드코딩하지 않는다.
- `CUDA_VISIBLE_DEVICES` 또는 컨테이너 GPU 격리를 우회하지 않는다.
- 동일 `gpuIndex`에서 활성 학습을 두 개 실행하지 않는다.
- CUDA OOM은 일반 예외로 숨기지 말고 안정적인 오류 코드와 메시지로 `FAILED` 처리한다.
- GPU 메모리 해제만 믿고 다음 작업을 시작하지 말고 기존 프로세스 종료를 먼저 확인한다.

## 8. 진행 상황과 heartbeat

AI 학습 코드는 `ProgressReporter`를 통해 진행 상태를 기록한다.

```python
reporter.report(
    "RUNNING",
    "TRAINING",
    percent,
    epoch=current_epoch,
    totalEpochs=total_epochs,
)
```

유의사항:

- `percent`는 0~100이고 뒤로 감소하지 않게 한다.
- `sequence`는 실행별로 단조 증가하며 프로세스 재시작 후에도 이전 값보다 커야 한다.
- 진행 파일은 임시 파일 작성 후 atomic rename 방식으로 갱신한다.
- 진행률과 프로세스 생존 heartbeat를 구분한다. 한 epoch가 길어도 `lastProcessHeartbeatAt`은 주기적으로 갱신돼야 한다.
- 로그에 Episode Presigned URL, 서비스 토큰, 개인 정보, AWS 자격 증명을 출력하지 않는다.
- 로그에는 최소한 runId, trainingJobId, attempt, stage를 포함하되 원본 센서 데이터는 출력하지 않는다.

## 9. CKPT 결과 계약

### 9.1 로컬 결과 위치

현재 엔트리포인트는 다음 상대 경로를 사용한다.

```text
checkpoints/{trainingJobId}/{attempt}/model.tgz
```

`checkpointStorageKey`는 공유 root 기준 상대 경로다. S3 key나 DB 경로가 아니다. S3 최종 key와 파일명은 EC2가 다음 정책으로 결정한다.

```text
ckpt/{owner_id}/{skill_key}/v{version}/{skill_key}_{YYYYMMDD}T{HHMMSS}Z.tgz
```

따라서 AI 코드가 S3 파일명, SkillVersion 또는 버전 번호를 만들면 안 된다.

### 9.2 완료 판정 순서

다음 순서를 모두 완료한 뒤에만 `COMPLETED`를 기록한다.

1. 학습 프로세스 정상 종료
2. 최종 CKPT 임시 파일 쓰기 완료
3. 파일 flush·close 완료
4. 최종 경로로 atomic rename
5. 파일 크기 확인
6. 전체 SHA-256 계산
7. CheckpointMetadata 생성 및 검증
8. 최초 `modelCompletedAt` UTC 기록
9. 완료 콜백 journal 저장 및 전송

부분 파일이나 쓰는 중인 파일을 완료 결과로 노출하면 안 된다.

### 9.3 필수 메타데이터

| 필드 | 요구사항 |
|---|---|
| `architecture` | 실제 모델 구조. 현재 기본값 `ACT` |
| `framework` | 예: `PyTorch` |
| `frameworkVersion` | 실제 학습에 사용한 정확한 버전 |
| `contractVersion` | Jetson 추론 코드와 합의된 모델 계약 버전 |
| `robotProfileId` | EC2에 등록된 호환 로봇 프로파일 ID |
| `trainingProfileKey` | 요청 profileKey 그대로 사용 |
| `trainingProfileVersion` | 요청 profileVersion 그대로 사용 |
| `trainingConfigSha256` | 요청 configSha256 그대로 사용 |
| `actionSpace` | 실제 출력 의미와 일치해야 함 |
| `nParams` | 실제 모델 파라미터 수 |
| `controlRateHz` | 추론 제어 주기 |
| `cameraNames` | 학습 입력 카메라 이름 |
| `inputSchema` | 추론 입력 tensor·state 계약 |
| `outputSchema` | 추론 출력 tensor·action 계약 |

학습기는 `frameworkVersion`, camera·input·output schema를 확정된 설정으로 기록하고, `nParams`는 실제로 생성한 모델의 `model.parameters()`에서 계산해 manifest에 기록해야 한다. `nParams`에는 환경변수 폴백을 사용하지 않으며 manifest 누락 또는 1 이하 값은 학습 완료 실패로 처리한다.

특히 `actionSpace`는 현재 환경 기본값이 `JOINT_ABSOLUTE`다. 학습 모델이 delta를 출력하면 `JOINT_DELTA`로 명시하고 Jetson의 ROS2 제어 입력과 단위·joint 순서·gripper 표현을 함께 합의해야 한다. 이름만 바꾸고 tensor 의미가 다르면 안 된다.

## 10. 실패 처리

- 예외 메시지를 그대로 외부 응답에 노출하지 않는다. 내부 로그에는 stack trace를 남기고 상태에는 안정적인 code/message를 기록한다.
- 입력 문제와 실행 문제를 구분한다.
  - 입력 hash·schema 불일치: 실행 전 4xx
  - CUDA OOM, 학습 프로세스 비정상 종료: `FAILED`
  - journal은 있으나 실제 상태를 복구할 수 없음: `LOST`
  - lease 만료: 실행 중단 후 lease 오류
- 일시적인 완료 콜백 실패만으로 학습 결과를 삭제하거나 재학습하지 않는다.
- 완료 콜백은 동일 eventId와 동일 payload로 재시도한다.
- 실패한 attempt의 CKPT를 다음 attempt의 성공 결과로 재사용하지 않는다.

## 11. 보안 및 경로 유의사항

- FastAPI 내부 API는 `FASTAPI_SERVICE_TOKEN` Bearer 인증을 유지한다.
- FastAPI → GPU Spring 콜백은 `GPU_SPRING_CALLBACK_TOKEN`을 사용한다.
- 토큰을 코드·이미지·로그·진행 파일·CKPT에 포함하지 않는다.
- 운영 토큰은 `.env.example` 기본값을 그대로 사용하지 않는다.
- 요청의 경로를 문자열 결합만으로 신뢰하지 않고 resolve 후 공유 root 하위인지 검증한다.
- ZIP 추출 시 Zip Slip, symlink, 과도한 압축 해제 크기, 파일 개수 제한을 검사한다.
- 모델 학습 코드가 외부 URL을 임의 호출하거나 AWS 자격 증명을 요구하지 않게 한다.

## 12. 환경변수

AI 연동 시 확인할 주요 환경변수는 다음과 같다.

| 환경변수 | 용도 |
|---|---|
| `FASTAPI_SERVICE_TOKEN` | GPU Spring → FastAPI 인증 |
| `GPU_SPRING_BASE_URL` | 완료 콜백 대상 |
| `GPU_SPRING_CALLBACK_TOKEN` | 완료 콜백 인증 |
| `WORKER_ID` | GPU worker 식별자 |
| `STORAGE_NODE_ID` | 공유 저장소 노드 식별자 |
| `SHARED_STORAGE_ROOT` | Episode·기준 CKPT·결과 CKPT 공유 root |
| `RUN_JOURNAL_ROOT` | 로컬 실행 복구 journal |
| `SUPPORTED_ALGORITHMS` | 지원 알고리즘 목록 |
| `GPU_COUNT` | 컨테이너에서 사용할 논리 GPU 수 |
| `MODEL_FRAMEWORK` | CKPT manifest framework |
| `MODEL_FRAMEWORK_VERSION` | CKPT manifest framework version |
| `MODEL_CONTRACT_VERSION` | Jetson 호환 모델 계약 버전 |
| `ROBOT_PROFILE_ID` | 호환 RobotProfile ID |
| `MODEL_ACTION_SPACE` | 모델 출력 action 의미 |
| `nParams` | 학습기가 실제 모델에서 계산해 manifest에 기록. 누락·플레이스홀더 사용 시 완료 실패 |
| `MODEL_CONTROL_RATE_HZ` | 추론 제어 주기 |
| `MODEL_CAMERA_NAMES_JSON` | 카메라 배열 JSON |
| `MODEL_INPUT_SCHEMA_JSON` | 입력 schema JSON |
| `MODEL_OUTPUT_SCHEMA_JSON` | 출력 schema JSON |

GPU Spring Boot가 CKPT를 S3에 올릴 때 AWS SDK 자격 증명을 직접 사용하는 것이 아니라 EC2가 발급한 Presigned PUT URL을 사용한다. FastAPI 및 AI 코드에 AWS Access Key, Secret Key, Profile을 추가하지 않는다.

## 13. 구현 권장 순서

1. 실제 AI 학습 진입 함수와 입력 인자 정의
2. Episode ZIP을 읽기 전용으로 여는 Dataset·전처리 adapter 구현
3. `FROM_SCRATCH` 학습 연결
4. 진행률·프로세스 heartbeat·취소 지점 연결
5. 임시 CKPT 작성 후 atomic 최종화 및 SHA-256 계산
6. 실제 CheckpointMetadata 생성
7. `FINE_TUNE` CKPT 호환성 검사 및 로드
8. 실패 코드 정규화
9. 재시작·lease 만료·취소/완료 경합 검증
10. GPU Spring Boot와 CKPT Presigned PUT 전체 흐름 통합 검증

## 14. 완료 전 체크리스트

- [ ] 동일 runId 재요청으로 학습 프로세스가 중복 생성되지 않는다.
- [ ] 요청의 `inputSnapshotSha256`과 training profile hash를 검증한다.
- [ ] 모든 Episode와 기준 CKPT의 SHA-256을 학습 시작 전에 검증한다.
- [ ] `inputOrder`를 유지한다.
- [ ] `FROM_SCRATCH`와 `FINE_TUNE` 동작을 분리한다.
- [ ] 지정된 논리 GPU만 사용한다.
- [ ] 취소와 lease 만료 시 자식 프로세스까지 종료된다.
- [ ] 긴 epoch 중에도 process heartbeat가 갱신된다.
- [ ] 진행률과 sequence가 감소하지 않는다.
- [ ] CKPT 쓰기 완료 전 `COMPLETED`를 기록하지 않는다.
- [ ] CKPT 크기와 SHA-256이 실제 파일과 일치한다.
- [ ] manifest가 실제 모델 입출력 및 Jetson 계약과 일치한다.
- [ ] 완료 콜백 재시도 시 eventId, 완료 시각, 결과 본문이 유지된다.
- [ ] FastAPI 재시작 후 journal과 실제 프로세스 상태를 대조할 수 있다.
- [ ] 로그에 토큰, Presigned URL, 원본 데이터가 노출되지 않는다.
- [ ] Python 단위 테스트와 GPU Spring Boot 계약 테스트를 통과한다.

## 15. 이번 연동 범위에서 제외할 사항

다음 사항은 AI 학습 코드에 포함하지 않는다.

- EC2 큐·할당 게이트 구현
- S3 업로드·다운로드 클라이언트 구현
- GPU Spring Boot의 CKPT 업로드 재시도
- 로컬 파일 보관·정리 API
- SkillVersion 생성 또는 배포 게이트 판정
- 웹 알림과 SSE 발행
- Jetson 모델 배포 및 로딩
